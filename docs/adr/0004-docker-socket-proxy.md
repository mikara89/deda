# ADR-0004: Docker Socket Proxy for Least-Privilege API Access

**Date:** 2026-02-21 **Status:** Accepted

## Context

Communicating with the Docker Engine requires access to `/var/run/docker.sock`.
Direct access to this socket grants root-equivalent control of the entire Docker
daemon — an attacker or bug in the autoscaler could stop, delete, or reconfigure
any container or service on the host.

## Decision

In the production deployment generated by `docker deda install` (via
`StackTemplate.cs`), a `tecnativa/docker-socket-proxy` container is placed on
the same overlay network as DEDA. Only the minimum capabilities needed for
autoscaling are enabled:

| Proxy env var | Value | Purpose                                                         |
| ------------- | ----- | --------------------------------------------------------------- |
| `SERVICES`    | `1`   | List and inspect Swarm services                                 |
| `TASKS`       | `1`   | Read task state per service                                     |
| `NODES`       | `1`   | Read node info (used for placement reporting)                   |
| `SWARM`       | `1`   | Read Swarm cluster state                                        |
| `VERSION`     | `1`   | Docker Engine version handshake                                 |
| `POST`        | `1`   | Required to issue `POST /services/{id}/update` (replica change) |

The DEDA container sets `DOCKER_HOST=http://docker-proxy:2375` and never mounts
the raw socket. The proxy container runs on a manager node and does not expose
port 2375 outside the overlay network.

The raw socket mount (`/var/run/docker.sock:/var/run/docker.sock:ro`) visible in
the commented-out `deda:` block in `deploy/swarm/deda-stack.yml` is the MVP /
local-development convenience form and is superseded by the CLI template for any
real deployment.

## Alternatives Considered

- **Direct socket mount (`/var/run/docker.sock`)** — zero extra containers;
  accepted for local development; rejected for production due to full Docker
  daemon access blast radius.
- **TLS-authenticated TCP endpoint** — proper mutual TLS provides granular
  access control without an extra container; rejected for v1 because certificate
  management in Swarm adds significant operational overhead.
- **Rootless Docker** — reduces risk of socket compromise but is not universally
  available across Swarm node OSes.

## Consequences

- A DEDA container compromise cannot affect containers outside Swarm service
  management.
- The `docker-proxy` container must be redeployed if additional Docker API calls
  are needed by DEDA in the future (e.g., reading config objects for HA
  locking).
- The proxy itself runs as a privileged container with the raw socket — it must
  remain on a manager node and be treated as infrastructure, not application
  code.
- For local development with `docker run`, the raw socket mount is acceptable
  and document as such in the quickstart.
