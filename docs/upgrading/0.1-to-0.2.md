# Upgrading from v0.1 to v0.2

v0.2 intentionally rejects malformed autoscaling labels. A missing label still uses its documented default, but an explicitly supplied invalid value now skips that service and records a configuration error. Check `min`, `max`, thresholds, cooldowns, steps, and `failsafe` before upgrading.

RabbitMQ services should move from `trigger.credentialsSecret` to an operator-owned policy file. Mount the policy into DEDA, set `DEDA_CREDENTIAL_POLICY_FILE`, and use `trigger.credentialsRef`. A policy binding defines the Docker secret, allowed endpoint hosts, and optionally the service names or IDs that may use it. The legacy label is disabled by default; it can be temporarily restored with `DEDA_ALLOW_LEGACY_CREDENTIALS_SECRET=true` for trusted clusters.

Reconciliation is now bounded by `DEDA_MAX_CONCURRENT_SERVICES` (default `8`) and `DEDA_RECONCILE_TIMEOUT_SECONDS` (default `120`). Readiness also expires after `max(DEDA_READINESS_MAX_AGE_SECONDS, 3 * DEDA_POLL_SECONDS)`.

For deployments that accept Docker socket access directly, use `docker deda install --docker-access direct`. This mounts `/var/run/docker.sock` and renders DEDA as root for deterministic initial access. Prefer the default `proxy` mode where the socket-proxy permissions are appropriate.
